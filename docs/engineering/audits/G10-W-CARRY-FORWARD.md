# G10-W — Carry-Forward

No `BLOCKER_IN_W`. CF-V-05 is CLOSED_IN_W and CF-V-01 is CLOSED_IN_W (see
`audits/G10-W-V-CARRY-FORWARD-DISPOSITION.md`). The items below are surfaced (or re-confirmed) by
the G10-W revision work itself and do not block the delivered claims.

| ID | Kind | Finding | Concrete trigger |
| --- | --- | --- | --- |
| CF-W-01 | **defect (fixed in W)** | `AggregateValidator.#validateTaskSatisfied` checked the whole `events` table for a `TASK_SATISFIED` with the promotion's `causation_id`, which on a clean replay matches the event under validation. Every project that had ever promoted a task failed `verifyFull()`/`rebuildProjections()` with `promotion already satisfied another Task`. Found by the W-A10 integrity invariant; fixed by excluding the event under validation. | Any `EventStore.verifyFull()` / `rebuildProjections()` on a promotion-bearing project. |
| CF-W-02 | semantics/contract | A plan revision cannot re-anchor the canonical head: `PlanInput` has no `headCommit` and `planReconciled` reuses `current.head_commit`, so after a promotion the ProjectIR head diverges from the real git head and a second task's promotion cannot satisfy `git.promote`'s expected-head precondition. All multi-task progress stalls at `needs_promotion`. | Any project with more than one promotable task, or any re-promotion after a plan revision. Fix = add an explicit, validated `headCommit` to the revision contract (or derive the head from the promotion projection) — never silently adopt the git head. |
| CF-W-03 | semantics | Evidence staleness for a typed invalidation is a post-commit projection repair with no event of its own, so it cannot join the atomic batch. A crash between the batch and the repair leaves evidence `active` that should be `stale` (fail-open on evidence authority; task authority is never lost). | A crash inside the second step, or any consumer that reads evidence status immediately after a committed revision. Fix = a canonical EVIDENCE_STALE event (wire change), not a hidden cache. |
| CF-W-04 | coverage | The `resume.action = "blocked"` branch of `#resumeOverview()` was reachable only through the CF-V-05 stale-input world. With the revision contract enforced, a public-API path can no longer produce an `ACTIVE` task authorized under an older revision; the branch remains as defensive fail-closed observation with no reproduction test. | A future feature that changes a project revision without settling/re-authorizing in-flight work (it must not). |
| CF-W-05 | product/route | `GET /api/manage/preview` returns the same `ManagementStepPreview` shape as the surface, but the web UI still derives its preview through an unconfirmed `step`; the new route is not yet consumed by `web/**`. | A UI change that wants preview without the step path. |
| CF-W-06 | semantics | `RETAIN_UNCHANGED` for a `READY` task whose dependency is a `STALE` task leaves the task `READY` in the projection; the dependency-derived state is only reconciled by the scheduler's own transition, not by the revision. | An operator expecting a revision to *recompute* dependency states of retained tasks rather than only re-authorize them. |
| CF-W-07 | scale | `planReconciled` reads the full `tasks` and open-`attempts` projections and mints one envelope per retained task on every revision; on a very large graph a revision is O(tasks) envelopes and events. | A project with thousands of tasks where revisions are frequent. Fix = a retention window or lazy re-authorization, never a partial closure. |
