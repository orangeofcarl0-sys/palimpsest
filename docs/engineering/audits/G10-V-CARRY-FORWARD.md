# G10-V — Carry-Forward

No `BLOCKER_IN_V`. CF-V-05 is a REAL, pre-existing Work-layer defect surfaced (not introduced) by
the G10-V dogfood; it does not block the G10-V management claims, but it blocks mechanical work
advancement after a plan revision and should be fixed in the Work layer.

| ID | Kind | Finding | Concrete trigger |
| --- | --- | --- | --- |
| CF-V-01 | product/route | No `POST /api/manage/recommend` or `POST /api/manage/preview` HTTP route. The application surface and the `palimpsest_manage` tool DO expose `recommend()`/`preview()`; the web UI re-derives candidates from `GET /api/manage/status` and calls `POST /api/manage/step {confirmed:false}` for its "Preview step". | A product/client needs a canonical recommend/preview endpoint distinct from the unconfirmed step, or the preview must be exposed without sharing the step's execution path. |
| CF-V-02 | product | No canonical management-action-history route. "Recent management actions" is UI session state only; there is no durable record of past management actions or their outcomes. | An operator audit/telemetry need, or a multi-session UX, requires a durable management action log. |
| CF-V-03 | product/semantics | The Work-Mode axis (`FOCUS`/`EXPLORE`/`COORDINATE` ± `VERIFY`/`MONITOR`) is not persisted or recorded anywhere reachable; the Management tab renders "not recorded by this installation". Only the management involvement is persisted. | A project-scoped work-mode setting is requested, or recipe/plan selection must be linked to the project rather than chosen per task. |
| CF-V-04 | product | `historySummary` merges only `ASSET_ASSOCIATED` and `JOURNAL_*` records; ProjectIR revision lineage and proof standing changes are read from the canonical owners elsewhere, not summarised in history. | The History tab must show ProjectIR revision lineage and/or proof standing transitions without extra reads. |
| CF-V-05 | **defect (Work layer)** | A `controller.plan(...)` revision AFTER task registration leaves the scheduler's stored task envelope at the OLD `project_revision`; the next activation (`controller.step()`/`controller.runTurn()` TASK_STARTED) fails its revision guard: `StateStoreError: expected revision N, current revision M`. Minimal repro: `start() → plan() → step()`. Not introduced by G10-V; the management *plan*-shaped actions are unaffected, but MANAGE's mechanical `runTurn` must run before any plan revision. | Fix by re-authorizing task envelopes on `PROJECT_REVISED` (or keying the activation's expected revision to the current project revision). Trigger: any workflow that revises the plan before the first activation. |
| CF-V-06 | semantics | `ADVANCE_MECHANICAL_WORK` is derivable only for a READY task with a non-terminal attempt; the deterministic dogfood injects that derived-view fact. The real product may rarely hold that exact state. | Attempt lifecycle/retry produces READY tasks with in-flight attempts (e.g. a failed batch settling back to READY while a sibling attempt runs). |
| CF-V-07 | harness/product | Refusal tests need to isolate a single candidate: some open-loop kinds derive both a refusal-shaped and a `RECOMMEND` candidate, and `step()` returns the first PERMITTED candidate, shadowing the refusal. The dogfood narrows the operator allowed set / replaces `openLoops`. | A product "why was nothing permitted / what blocked this" surface is wanted; then isolation is a product concern, not a harness hack. |
| CF-V-08 | semantics | Journal `relatedRefs` are `{kind, id}` only; there is no cross-project asset link and no cross-project workspace view. | A user asks to link assets across projects, or the external Personal Asset System boundary is opened. |
| CF-V-09 | scale | `ProjectWorkspaceService.assets()` replays every known project scope with no pagination; fine for one/few projects. | A deployment hosts many projects and the assets read becomes a hot path. |
| CF-V-10 | boundary | The external Personal Asset System is described (`PERSONAL-ASSET-SYSTEM-BOUNDARY.md`) but never implemented: no `ExternalAssetLibraryPort` type, store, route or tool in `src/**`. | An explicit user/operator request to import from or publish to a personal library — then implement it as proposal-only, never auto-index. |
| CF-V-11 | deployment | The management preference store is deployment-local and non-authoritative; there is no export/portability or shared operator preference. | A multi-host deployment needs one operator involvement decision to span hosts (it must stay a preference, never authority). |
| CF-V-12 | relations | `campaignProjectRefPort` (`src/install.ts`) skips a campaign whose linked-project projection reports an identity conflict rather than guessing; campaign relations are therefore incomplete-but-honest for that campaign. | A campaign needs a reconciled linked-project identity, or an operator needs an explicit conflict report. |
