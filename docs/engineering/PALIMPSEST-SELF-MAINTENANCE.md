# Palimpsest 自维护试点

Palimpsest 可以把自己的维护工作作为普通项目处理。目标是让运行中的版本把一次故障变成可复现工单，产出绑定完整 Git SHA 的候选，再由原运行环境之外的检查和接受流程决定能否启用。下一次会话读取原故障、接受版本与验证依据，继续处理真实维护任务。

## 已有基础与缺口

| 能力 | 已有依据 | 本轮判断 |
| --- | --- | --- |
| 调查自己的仓库 | 上一次重启交接用真实产品仓库和归档。Palimpsest 定位了历史结论与待办分类问题，未提交原稿。 | 能做部分维护工作，调查、验证和提交能否在同一窗口内完成仍待观察。 |
| 独立交付与受保护接受 | 普通 DSH 支持直接提交和 `DELIVER`。Energy 跑通过正式 Worker、结算、完整 SHA 核准和后续会话接续。 | 可以复用两条路径。对自身代码的第一次窄试点用本地候选验证链，正式接受由运行方独立完成。 |
| 复用已验证的方法 | `procedures` 支持候选、准入和适用范围。`institutional_learning` 读取已有结构演化与评估记录，结构变更仍由既有权威路径批准。 | 先验证相似维护任务确实能复用一条经验，再考虑晋升成默认方法。 |
| 更换正在运行的版本 | 现有部署能从已构建产品启动，也能从持久记录冷恢复。 | 新版本应在隔离副本启动，用旧状态副本检查读回和回滚。核心运行时、评分与权限单独审核。 |

## 首张工单

上次真实交接中，两组在依赖只读的 Linux 环境都遇到 Vitest 配置加载失败。Palimpsest 到第 44 笔才首次改源码，强原生 DSH 到第 36 笔。从故障复现到提交还有工具链摩擦，但现有对照没有给出它独自消耗的请求数。两组各到 64 笔，未提交、未自然退出。离线原判保留 11/15 和 9/15。先修这张小工单，可以在下一次实跑中把测试启动问题与复杂业务调查分开归因。

工单要求提供一个稳定的 `node --run test:focused -- <测试路径>` 入口，只允许在 `package.json` 增加这一条命令。独立验证运行两份现有交接套件，再加入由宿主写入的失败测试，核对命令是否实际执行该测试并返回失败。候选的其余 manifest 语义及所有其他文件均与基线比较。基础镜像与既有交接实验相同，基线使用 `origin/main` 的完整 SHA。

普通 DSH 从基线构建并加载产品。工作副本在独立 Git 卷内。Mock 通过现有 PNWF 代理和账本读取 Pulse、验证参考改动、提交、登记 `DELIVER`、自然退出。宿主从候选 Git bundle 启动另一份无网络的检查副本。原会话无须接触检查副本或失败测试。脚本化工具选择验证执行链，真实模型如何定位和修复由后续轨迹观察。

资格诊断保留了三个初始现场。第一次预检只识别 `EROFS`，容器实际在同一 `.vite-temp` 创建步骤返回 `ENOENT`。修正后另行确认依赖存在且不可写。第二次在 Mock 的零基请求序号上偏移一位，会话正常退出，未形成候选提交，宿主拒绝。第三次用 `pnpm` 启动时，普通 DSH 的只读主目录阻止它创建 `.local`。Shell 结果有具体错误，轨迹仍把工具回传记为成功，随后调用 `DELIVER` 得到 `RECORDED`，Git HEAD 却仍在基线。宿主依据 Git 核验拒绝了该候选。最终工单改用 Node 自带的脚本入口，脚本化会话在观察到提交后才登记交付。

```powershell
$run = Join-Path $env:TEMP ('palimpsest-self-maintenance-' + [guid]::NewGuid())
node scripts/pnwf/software/self-maintenance-qualify.mjs $run
```

复算保留 `baseline.log`、逐请求 SQLite、按调用 ID 配对的 JSON、完整候选 SHA、`candidate.bundle`、正反例日志和 `qualification.json`。Mock 候选留在独立 Git 成果内。

## 如何判断后续实跑取得了自改进

**第一跳是完成维护。** 从同一基线交给 Palimpsest 和强原生 DSH，同一业务提示，同样的工具链和只读依赖条件。模型自己决定先查档、复测、委派还是直接修。只有冻结验收通过、候选已提交、交付引用可取回且会话自然结束，才记为完整初次交付。分开记录可用原稿、候选通过、接受和退出。若另一个 Agent 给出实测，跟到它改变的提交、测试或判断。

**第二跳是复用改善。** 由所有者核准确切候选 SHA，分别构建旧版和接受版。用全新会话给两者一张相邻的真实维护工单，不复用会话历史。两组可读同一份原故障记录，分别从各自版本的正常入口开始。分别统计第一次通过定向测试前的请求、启动失败和重试、有效修订、交付收尾、用量与人工等待。若入口是共享代码，两种 DSH 都能受益。Palimpsest 的额外收益应由可追溯的接受、接续读取、复用或少返工另行证明。单个配对用于诊断，稳定收益按路线图的重复配对证据判断。

**第三跳才涉及产品本身的演化。** 下一张工单可选产品读路径中的真实故障，由旧版 Palimpsest 产出修改新版的候选。独立环境用原档案构建和冷启动新版，核对旧账本、接受记录、API 兼容和一项新业务回归，并保留能够重新启动旧版的副本。受保护接受走既有 Work 回执和 Operator。候选代码、评分器、当前执行宿主和发布凭据保持独立，批准对象是完整 SHA。遇到工作义务越界、基线漂移或回执不符，沿用现有拒绝路径。

工作变更、方法晋升和版本启用各自有清晰的批准对象。普通维护会话可以把已验证的方法留为带试验依据和适用条件的候选。实际使用过该方法的新会话，才提供可复用经验的证据。 [项目路线图](../product/PROJECT-ROADMAP.md) · [共用候选回执 SDK](../sdk-guide.md)

## 真实自维护配对

两组均从 `02a5160c2361bb70a2127574a76ea6e571b296a8` 和同一已通过 Mock 的中文业务工单启动。普通 Palimpsest 及强原生 DSH 使用各自的全新 DSH home、独立 Git 卷和请求账本。同一镜像核验 DSH `0.2.1-rc.5`。模型为 OpenCode Go `deepseek-v4.1-flash`。每会话 64 笔、30 分钟、单请求 240 秒，按量记账，金额和总 tokens 均无上限。试验卷内的 Git 身份用于候选证据。产品与原生 DSH 都可自行调查或调用各自具备的协作工具。

### Palimpsest

Principal 先用 Pulse 确认工单，再读取原交接报告和 manifest。它检查依赖符号链接与权限，并自行做因果对照：第 6 笔的 Bash 83→86 实测默认加载器在 `.vite-temp` 创建失败，返回内层 `EXIT:1`。第 7 笔 91→94 仅改用 runner，原套件 9/9。随后查看旧运行器的既有做法，再在 115→116 写入 `test:focused`。因此这里是查档加实际复测，定位者是 Principal。全程无委派和同伴求证。

新入口单套件 9/9、两套件 20/20。Principal 自建一份临时失败断言，通过新入口读到退出码 1 后删除。Shell 作业本身因用 `tail` 和 `printf` 显示子进程结果而返回 0，所以通用工具统计为 0 个失败作业。实际测试启动失败和主动负控按配对后的完整结果分别记录。两次 Bash `rg` 不存在也按结果单列，随后用 DSH 的 `grep` 和系统 `grep` 调查。提交调用 165→168 以 `git add && git commit` 组织，归因计数没有把它分类为独立 commit 工具；实际 Git 对象和回传均确认提交。随后 181→182 登记绑定工件的 `DELIVER` 并自然退出。

独立验收、正反例及工件摘要全部通过。候选 `072ff2e6defdb4ff3b1f08be340bd3c931ab7ae9` 得到所有者按完整 SHA 核准，接受版本在隔离 Git 副本固定为同一提交。18 笔请求全部结算，调用与结果 30/30，fresh input 52,624，cache read 636,672，cache write 0，output 8,285，共 697,581 tokens。会话运行耗时 235.646 秒。

## 新会话的旧版与接受版对照

第二张工单修复普通 Work 的一处真实矛盾：没有正式任务时，干净的新 Git 提交可以直接记录 `DELIVER`，`readiness` 却返回 `CONTINUE_WORK`，建议先 plan 或 begin。交付结论已经记录后，同样提示继续工作。宿主从 `02a5160c` 构建并复现，独立探针的 6 个判据通过 4 个，失败项正是新提交的引导与已有交付结论的引导。未改动、未提交、直接交付记录和 Operator 基线保护的四项均通过。

两个接受后的观察臂均使用普通 Palimpsest，各有新的 Git 卷、项目状态和 DSH home。旧版开始于 `02a5160c`，接受版开始于获准的 `072ff2e6`。业务提示和独立探针相同，提示仅描述故障与交付约束。以配对的 Shell 调用与完整结果识别实际测试调用、失败及重试。帮助查询或读取脚本不计测试。测试进程在配置时退出、业务断言失败、刻意负控与外层 Bash 状态分别记录。比较总请求、首次测试通过前的请求、模型用量分项、耗时和候选验收。
