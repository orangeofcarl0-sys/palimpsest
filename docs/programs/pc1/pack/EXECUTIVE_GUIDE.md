# PC1 人类总览：这次“一杆捅到底”具体意味着什么

## 1. 不是让 Agent 任意改架构，而是让它完成一条真正的产品交付线

长期愿景保持：面向大多数复杂长期任务，让不同 Agent 的独立工作被理解、检验、继承，最终共同改善项目。近期交付目标则收敛为一个 **DSH 原生的项目协作产品候选**：创建/继续项目、看清当前状态、按需协作、提出行动、合法接受结果、中断后继续。

不会把 Top-Down × Bottom-Up 延伸成三套递归控制平面。不会因为已有 organization、institutional_learning 或 runtime_evolution 目录，就把它们全部加进默认路径。也不会把 Palimpsest 缩成只读档案库。

## 2. 十一阶段，一次完整推进

| 阶段 | 交付焦点 | 看什么才算完成 |
|---|---|---|
| S00 | 基线、能力盘点、整体执行配置 | 有干净新分支、现有 owner 映射与可执行计划，不停在审计 |
| S01 | Result/Evidence/Promotion 完整性 | 真实结果可以合法接受；结构性证据无法由任意命令冒充 |
| S02 | 默认产品路径收敛 | 普通 Agent 不必研究框架内部状态机即可完成正常工作 |
| S03 | 项目认知连续性 | 新 Session 能区分当前承诺、历史结论、候选与未决问题 |
| S04 | 提案—批准—执行 | Agent 生成的行动候选获得精确批准后能进入已有 Work |
| S05 | 有实际价值的多 Agent 合作 | 独立认知贡献改变其他参与者行动；长期 peer 与临时 branch 分清 |
| S06 | 非编码成果与业务结果 | 正确负面发现可采用，调查完成不会假装业务目标达成 |
| S07 | 运行、隔离、恢复与成本 | 不靠 Prompt 假装权限；任务/结果/预算可观察、可恢复 |
| S08 | 场景与强基线评估 | P/F 事实和能力等价，真正检验价值，不预设 Palimpsest 赢 |
| S09 | 安装、文档和可用性 | 新用户从可重复安装进入主路径，不操作内部 SQLite |
| S10 | 集成资格与最终交付 | 全范围变更审查、回归、制品、演示和准确成熟度判断 |

S00→S01→S02 是优先路径。S03、S06、S07 等可在接口明确后并行推进，S04/S05 完成后汇入 S08。S09 可早做骨架，最后统一检验。阶段依赖详见 `tracking/program.json`。

## 3. 开发授权更宽，真实世界权力不增加

本地 Agent 获准在新分支实施整个范围内的必要代码与接口变化，保留兼容层、修复普通产品入口、补齐现有服务的投影和接入。不需要每个 spec 再请求一次确认。

但这不授权它：充值/升级模型账单、导出凭据、提升沙箱权限、修改真实项目的外部资源、直接合并 main、清理历史 worktree、改写 frozen evidence，或发明一个能自批权限的 Agent。

## 4. 不打折扣的定义

不削弱强 DSH 基线；不把 deterministic Worker 称作真实模型；不把作用域不明的 Gate PASS 称作业务真理；不把读取历史当作多 Agent 合成；不把 Provider Blocked 称作模型失败；不为了完成计划撤掉安全门。

另一方面，不能用“需要更多审计”永久代替实现。每个发现必须归入：本期修复、已证实不适用、资源阻断、受限授权、或带有明确理由的剩余风险。没有证据的空泛 postponement 不合格。

## 5. 建议首先观察的结果

这次最重要的不是新增了多少模块，而是：一个真实 Agent 的合法成果能否从执行世界进入正式项目；它是否能继续处理现实变化；不同 Agent 是否提供新的独立判断；新 Session 是否不用重建全部历史；相对成熟 DSH 是否减少错误、重做或人工协调。

历史 C6-R 中的短 SHA 根因是 **争议结论**，不是本包指定答案；本包要求对原事件、对象可达性、路径视图和效果账本重新归因。原观察记录不得因修复成功而改写。

## 6. 使用方式

把整个 ZIP 解压后交给本地 Agent，并要求从 `AGENT_EXECUTION_PROMPT.md` 开始。无需逐个粘贴阶段文件。Agent 维护 `program-state.json` 与检查点，即使上下文中断也应按同一计划恢复，而不是启动另一套 COG 架构。

本包提供的测试工具已针对文档与工程记录约束自测；它们不表示产品实现、模型实验或新分支已经由本次聊天代为执行。
