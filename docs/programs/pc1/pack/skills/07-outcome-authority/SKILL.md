# palimpsest-outcome-authority


## 步骤

1. 将问题拆为 execution completed、artifact delivered、Work contract satisfied、domain finding supported、business goal attained 五个命题。
2. 检查任务原文：“调查并报告”与“提供满足全部约束的方案”不是同一合同。不可行结果可完成前者，不满足后者的目标。
3. 追踪 plan/decision/Opportunity/Intent/Promotion 各自实际 owner 和 authority。文本 decision、tool mode 和管理偏好不自动授予外部批准。
4. 对 proposal 形成精确 review 包：scope、source/proposal digest、project basis、未决问题、费用与 required role。批后再查 currentness；race 使用原 CAS。
5. negative 进入合格 Journal/结果引用，但不自动增加工作或降低要求。让 Agent 决定是否有价值的 follow-up，operator 决定权限。
6. 检验 independent evaluator 是否读到了实际检查对象；命令因 applicability 未执行时不能声称领域验证通过。

## 输出

outcome/authority matrix、review receipt、业务目标未满足的可见说明与合法下一步。不得新增万能业务真值 owner。

## 反例

缺证书但报告文件存在、Site B 无合规供应商但调查接受、approve A 后 B 改了 bytes、Task 已创建但 source 未批准、Journal decision 被误读为采购承诺。
