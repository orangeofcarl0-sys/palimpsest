# PC1 总体指导：以真实项目能力收敛整个系统

## 目标与衡量

Palimpsest 的定位是长期项目中的多 Agent 协作与智能合成系统。可信项目资产是基础，自发合作是行为，合成质量是需要验证的价值。三个方面不可相互代替。最终应能回答：用户不反复交接背景的情况下，多名可替换的 Agent 是否共同完成了更好的工作。

本期采用三个产品层次，而不是新增三个控制面：

- **默认项目助手**：正常 DSH 推理与工具、项目当前视图、轻量知识记录、按需读取。没有正式效果时不强迫建立整套 Work/Promotion。
- **受治理工作**：对版本化产物、共享承诺、外部效果或重要接受决策启用既有 Work、验证、Promotion、Recovery。
- **协作合成**：当信息独立性、领域互补、冲突核对或真正并行工作有价值时组织多 Agent；否则允许 Principal 独立完成。

这些是产品配置/呈现目标，不自动对应新增 canonical enum；优先映射已有 management involvement 与工作模式。

## 必须完成的主路径

用户进入项目 → 当前目标/约束/成果/候选/未决问题 → 自然发现新信息 → Agent 提议或授权范围内的调查 → 必要的独立协作 → 与实际动作分离的批准 → 执行/验证/接受 → 新 Session 继续。

在任何节点，系统应能向普通用户/模型解释：现在是什么情况、有哪些证据、可以做什么、为什么不能做什么、还需要谁决定。内部状态机名称保留给专家面，不成为默认交互的主要语言。

## 复用与职责

DSH 负责模型调用、Session、基础工具和可用的原生 Subagent；Ordarium 负责其已定义的安全效果与恢复。Palimpsest 负责项目承诺、Work/结果身份、来源与接受关系、上下文投影、跨参与者的成果延续与正确行动。

Super-agent 的重要启示是持续工作不应绑定一个 Session、收到上下文不等于获得授权；LayerFS 的重要启示是执行隔离与版本化应该由适当基础设施承担。二者不是本期需要复制的整体系统，也不是已获批准的依赖迁移。用户提供材料对 Pi Durable、Context Topology 的讨论是设计参考；不将任何个人经验提升为普遍模型定律。

## 现有资产的处置

对每个核心模块标记：默认核心 / 按需高级 / 保留研究 / 兼容维护 / 证据支持的替代候选。依据调用图、产品工作流与运行证据分类，不凭目录名字删除。

Work、Result、Evidence、ProjectIR、Promotion、必要 Currentness 与 Recovery 保持其权威；Workspace/Journal/Context/必要 Trajectory 提升可发现性；Intent/Proof/Organization 等按用例接入。Institutional Learning、动态拓扑、架构自修改不扩张为本期目标。

## 简化纪律

允许删掉默认路径的重复工具、重复提示与无收益步骤，但不得删除历史证据或默默弱化权限。新的 facade 只能组合现有 owner，不能缓存第二份 canonical 真值。每个新增状态字段说明 owner、生命周期、来源和失效规则。看起来方便但无法归属的字段先做派生视图。

产品化不能只做一层漂亮包装：normal DSH path、CLI 和实际执行必须使用同一工作语义。实验驱动器不能成为唯一会正确调用产品的程序。

## 明确非目标

不重造 Harness；不强制所有工作都走强治理；不建设通用真理引擎；不默认增加 Agent 数量；不做递归元控制器；不为证明兼容性建立新跨平台文件跟踪系统；不因热点切换到 LayerFS/Pi；不把 Artifact Hash 当作内容真实或语义正确的证明。

## 成功与失败均可用

代码完整性是本期义务，实证优势是待检验结果。若强 DSH 基线等效或更优，保留负面结果，并将本期产品以更窄、风险相关的定位交付。不能为提高分数让人替模型做提议、改变 Oracle、过滤失败或降低 F 条件能力。
