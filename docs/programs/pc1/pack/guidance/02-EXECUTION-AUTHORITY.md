# 执行授权、边界与继续推进规则

## 1. 本期授权范围

用户要求在一个新分支上完整落实此前总体反思。Agent 因此可实施所有 S00–S10 范围内的产品接口、适配器、投影、测试、实验、安装、迁移脚本和文档。允许为打通真实主路径作跨模块重构、添加正常产品工具、整理默认 Tool Registry，并在既有 owner 下新增必要派生数据或向后兼容字段。

不再要求每个局部修复只能几行，也不要求所有新增接口再次报批。合理性由需求、风险、已有所有权和验收测试共同约束。

## 2. 硬边界

以下未获授权：移动/合并 main，打开或合并 PR（可生成本地 PR 草稿材料）；force push/rebase 历史；删除历史 branch/worktree/locks/evidence；手工改 Ordarium ledger 或伪造效果事件；访问真实业务外部系统作写入；更改计费/充值/新建密钥；在未隔离环境中让模型拥有宿主全权限；让模型自行批准高影响变更；以替代 provider 混入既定 scored cohort。

正常读取用户已连接仓库用于审计是允许的。现有秘密只可经被授权 Host 配置使用，不进入模型 Shell、实验目录、截图或日志。测试只用 synthetic canary。

## 3. 在新分支内可以决定什么

可自行决定内聚的产品 API 命名、正常/专家工具分层、派生视图结构、Context 包格式、测试实施方式、兼容层、程序诊断与人工审核 UI。添加非权威 proposal/handoff metadata 是允许的，但不能让它成为第二个接受账本。

对数据迁移：必须幂等、有 dry-run、有备份恢复测试、不覆盖旧事件；默认应用于测试 clone。真实用户库迁移的自动执行须已有操作员授权；否则交付工具与预演结果。

对依赖：复用现有 DSH/Ordarium API；确需小型依赖时说明必要性、锁版本、许可证与离线复现，不引入新 Runtime 或大平台作为捷径。

## 4. 继续推进而不是反复停工

发现阶段阻断时写入 blocker，标明 dependency 与可以继续的节点。选择下一个依赖已满足的工作，不输出一份审计后终止全部计划。

- Provider 余额不足：停止付费调用；继续所有实现、确定性集成、打包、场景、评审材料。真实行为状态保持 BLOCKED。
- 原始 pending operation 无法恢复：保持历史；在独立复现中修复新路径；不修改旧账本来获得 PASS。
- 必须新增权限根：隔离该特定效果；先交付候选/审核/受拒绝状态和已有合法路线，其余阶段继续。若仍无法实现核心能力，最终明确 gap，不能称完整通过。
- 发现一条测试失败：保留原始失败，定位再修复；不得重复到偶然通过。
- 时间/上下文不足：写检查点、精确下一步和测试状态，后续按相同分支/计划恢复；不启动另一套架构。

## 5. Branch 基线偏移

默认从冻结 `044b080...` 创建 `palimpsest-product-convergence-v1`。若目标分支已存在且包含同一 programme marker、同一 source ancestry 与可验证检查点，允许继续，不另建编号分支。若同名 unrelated，选择带执行日期的唯一后缀并记录，不能覆盖。

若来源已前进：只读比较变更，保留本包冻结基线；除非确认后续提交与计划兼容且检查点完整，不自动 rebase 或掺入评分 cohort。可在独立干净 worktree 使用冻结基线继续，不动用户脏树。

## 6. 模型资源

本包**不自动提高之前任何已批准 campaign 的额度**。执行前选择已有明确资源授权与本期计划的更严格限制。没有可复用且未耗尽的授权时，默认 `spendAuthorizationRef=null`，只做零模型工程；把 live trial ready 与 live verified 分开。

供操作员一次性采用的建议本期窗口：24M 报告 Token、24 个模型 Session、在途预留 6M；这是新窗口的建议值，不是自动批准账单。预算按匹配对预留，不允许一个 P 单跑耗尽后仍声称比较完成。真实货币支出限额由可核实价格或账户授权决定，不凭缓存 Token 总数猜费用。

## 7. 推送与交付

可在核对 remote 目标与无并发推进后 non-force 推送本期新分支。若无 GitHub 写权限，保留本地提交并生成 bundle/patch。不得因此放弃本地完整实现。正式 main 集成留待 owner；本期必须交付完整 integration qualification 与 PR-ready 材料。
