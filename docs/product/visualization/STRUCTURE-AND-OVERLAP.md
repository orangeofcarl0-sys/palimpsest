# 多智能体协作图中的组织、世界、动态关系与交叠集合

2026-11-18 · Palimpsest 设计提案 · 对照现有 DSH、组织与世界模型、可视化原始研究及两组 Git 归档

人在 DSH 里同时需要三种方向感。第一种是「我站在哪个组织和工作世界里」，第二种是「谁刚对什么做了什么」，第三种是「哪几个对象同时满足我关心的两种条件」。建议把它们放进当前会话的**协作**页。树提供可返回的地址，工作对象落在可局部生长的格点上，选中的集合用有名字的轮廓圈出成员。点一个对象就能看到动作、版本、成员依据和原件。切到**成果**沿用同一选择，追查它后来被谁采用。[交互研究样例](prototype/structure.html) · [DSH 位置规划](PLAN.md#工作视图放在哪里)

## 一、硬的是哪一层

| 要回答的问题 | 持久对象与时间尺度 | 屏幕表达 |
| --- | --- | --- |
| 组织怎样组成，当时谁担任什么角色？ | 组织定义按修订发布，成员、角色、任命与声明的交互各有字段。正式拆分或合并有独立的激活过程。 | 结构栏列出组织及修订，展开可读角色与成员。一个人同时任职两处时，两条目录引用都选中画布上同一个有类型的主体。 |
| 这份工作在哪个世界，比较用的依据是什么？ | 项目、Attempt 的授权依据、执行副本和接受后的项目 Head 各有引用。世界依据还可包含语义、资产和环境，部分维度可能未知。 | 世界有独立的目录和带名称的工作区域。框内工件标明其归属版本。跨世界沿用引用、派生或晋升用有名称的边。两个世界包含相同字节时保留两个来源。 |
| 正在发生什么，哪些东西刚改变？ | 会话、执行者、发现、问题、工件版本及其动作。生成、失败、重试、交接、退出和采用都可能分别发生。 | 在格点上放可选中的主体和对象。新版本从原对象附近出现。点选后展开一跳的有向关系，每条写出动词、依据及所处时点。 |
| 哪些对象有双重身份？ | 一个集合有成员类型、纳入条件、适用范围、时点及来源。组织成员、协作联盟、边界工作区参与者或文件义务都可以构成集合。 | 在保持位置的成员上叠加至多两个具名轮廓作为初始方案，显示确切交集数，点成员可读每个归属的依据。其他集合按需替换或进入矩阵。 |

「偏硬」描述变更的条件。组织正式换版、执行世界另立基线、项目接受新 Head 时，界面要让人看见**哪一个参照发生了变更**。成员加入一次协作、临时接手一个文件，则只更新相应关系。组织与世界也是两个维度。一个组织可以在两个世界工作，一个世界也能容纳多个组织的贡献。目录表达可核对的包含、任命或版本来源，有多个来路时显示引用与沿革。组织定义本身还含多对多关系，画布不会给每个主体发明唯一上级。[组织定义](../../../src/organization/definition.ts) · [组织演化](../../../src/organization/transformation.ts) · [工作世界依据](../../../src/domain/world_basis.ts) · [运行作用域](../../../src/runtime_scope/artifacts.ts)

综合选择是一张**有固定参照的工作图**。全量力导向图适合探索未知联系，但刷新后换位会增加找回同一对象的难度。单一树在双重归属时必须重复节点或损失信息。把所有集合都铺上颜色，在成员分散时会遮住工件。把矩阵作为唯一首页又会失去具体执行者及工件所处的世界。需要比较成员数量时，用户可以在同一范围下切换矩阵，再回到先前选中的对象。

**先排工作对象还是先排集合，已有直接的对照研究。** Rodgers 等用静态图比较五种同时呈现网络与重叠集合的方法。在他们选择的组合任务中，先排集合的 EulerView 和 SetNet 比先排网络的 Bubble Sets、KelpFusion 和 LineSets 答得更快。这给我们的选择划出了边界。值守时保留刚才工作的空间位置有理由，专门调查「同时在两组中的人把哪些工件交给了组外成员」时，适合允许一次显式的按集合重排。读者能返回原工作位置，两种排法分别测正确率和耗时。KelpFusion 在既有坐标上随局部密度以线或面表达同一集合，也可作为分散成员的对照。其细连接在这里需要和有方向的交付箭头做辨认实验。[五种方法的直接比较](https://www.cs.kent.ac.uk/people/staff/pjr/SetNetPostPrint.pdf) · [KelpFusion 作者论文](https://pure.tue.nl/ws/files/90842832/KelpFusion_TVCG_2.pdf)

**时间也能当主坐标。** TimeSets 用时间顺序排列事件，同时表达一项事件属于多个主题。这适合回答「某次加入、一次发现、后来的采用隔了多久」。在 DSH 当前协作页，用户仍要回到手边的工件。切某个时点时可以保持对象的位置；追问演化经过时，再以时间为轴打开同一组对象的事件记录。这样两个视图都沿用同一成员定义和选择。[TimeSets 作者论文与设计比较](https://vis4sense.github.io/timesets/paper.pdf)

## 三、三种形状如何共处

1. **树与框分别带语义。** 左侧组织树和世界树独立折叠。用带名称和版本引用的矩形框标出工件的工作世界。组织目录中的别名可高亮同一主体，过滤只改变可见范围。目录的展开顺序、节点的屏幕距离都不能用来推断权限、亲缘或信息流。
2. **格点是排版坐标。** 稳定键由已授权的读面、项目和带命名空间的对象标识组成。版本指针另存。新增节点优先尝试产生它的世界或邻居周围的空位，同分以稳定标识排序。先避开重叠、固定点和别的世界框，再优化边长、交叉和旧节点位移。若局部放不下便扩展该区域或把支线折叠成可展开的对象数。用户主动重排时才允许整图重新找位。配置的协作拓扑、运行时的动作和时间相邻分别显示。[既有五种投影](../../../src/application/projection_types.ts) · [关系依据等级](../../../src/trajectory/refs.ts)
3. **圈在同一成员域里求交。** 先选「哪些 peer」或「哪些候选文件」以及观察范围，再计算 A、B 和交集。一个 peer 参与三方协作可由一个集合或一次有参与者的协作事件表示，不能补画三条两两通信。若 A 是组织中的 peer、B 是运行中的 Activation，要先有可核对的身份绑定再投影成同域。集合共属、共享同名路径和世界兼容性各用各自的证据。[组织身份键](../../../src/organization/definition.ts) · [执行关联](../../../src/execution_association/contract.ts) · [跨依据准入](../../../src/project_world/cross_basis.ts)
4. **位置让给事实，动效让给变化。** 节点新生占相邻空格，退役留在过去切片。替代版本保留前件引用。成员进入或退出只改轮廓和成员标识，工件与已经发生的贡献仍可查。跨世界交付用一个有来源的指向关系。若接收方实际生成新版本则画出新对象。组织拆分/合并保留旧修订与各个后继，世界指针推进保留原基线。颜色以外再给实/虚线、字母、动作标签和可按键阅读的记录。
5. **几何有可核验的退路。** 轮廓生成后逐一核对可见成员标记。只要夹入非成员、遮住标签、穿入难以辨认的第三组，便改用边框内的同名成员标记和名单。集合跨两个世界很远时，各世界分别标出同一个集合名与合计，不用大色块覆盖中间区域。超过两个集合或主要问题变成「哪个组合最多」时，切换矩阵。矩阵明确区分「包含 A 和 B，可另属 C」与「恰好 A、B」，点击计数列出确切成员。两组是拟试的默认值，密度和误读率决定最终取舍。

## 四、时间、选择和可见范围

用户打开会话时看当前切片。点一个人，工作面加强这个人与邻近对象的有据动作，其余结构保留作参照。选世界可查绑定版本，选工件可读来源与差异，选轮廓可读纳入条件及成员。手动选择固定观察位置，继续接收更新。查看过去则另外固定依据和事件位置，提示有新事实可返回现场。窄屏把参与者放在上方、工作世界放在下方，同屏保留整条交接。成员表和图共享时点与选择。

在可操作样例里，首次打开会短暂重演「留下注记」。复核助手旁出现「签注 N1」，一张小纸片沿签注边进入 W1，随后一个点沿引用边回指已有的比对表 C1。退出复核时只淡去以前的成员边界，比对表及注记继续留在副本中。「播放经过」从取样走到组织换版后停住。点人或工件会暂停并固定对象。点已有动作的「循线」，可以留在当前时点，核对当初记录动作的双方。启用系统减少动态效果时，动作标签、端点、成员数和工件位置给出同样的事实。[会话内交互样例](prototype/structure.html)

三个时点各有意义。界面分别记录动作发生、宿主观察和正式修订生效。读取时携带各所有者的依据及序号。缺少可比时钟的两条流按可证关系连结，其他观察并列。世界变更时重新评价该版本上的集合，旧切片仍按当时的世界计算。权限过滤先于布局和计数。来源不完整时可显示「已确认 2 名，其余未观察」，拒绝访问时只显示允许披露的范围说明。只有明示的完整可见成员域才能给出确切的零。[依据向量与分页](../../../src/trajectory/contract.ts) · [来源披露](../../../src/proof_asset/disclosure.ts) · [缺失与未要求的世界维度](../../../src/domain/world_basis.ts)

## 五、用 Palimpsest 的记录反推设计

**同一人可处在多层交集。** `F5-OVER` 的同一 `peer-a` 同时出现在两个正式组织和两个 Coalition 快照。它在图上应该只有一个带命名空间的身份，能从四个入口找到。`G10-L` 的成员变更用例里，Palimpsest、Ordarium、Reasoner 完成该次所需核准后，Reasoner 才列入边界工作区 W 的参与者。该记录没有同时产生组织任命或新承诺。两项用例来自不同夹具，各有自己的范围。[组织与联盟重叠](../../../test/f5_integration.test.ts) · [边界工作区的成员变化](../../../test/l_federated_boundary.test.ts)

| --- | ---: | ---: | ---: | --- |
| 执行基线 `fbeb8958` | 4 | 3 | 1 | `test/rest.test.js` |
| 晋升后的项目 HEAD `4639ae44` | 8 | 3 | 3 | 上述文件及 `test/integration.test.js`、`test/server.test.js` |

复算时将各自的 `candidate-and-accepted.bundle` 克隆为临时裸库。全集从 `candidate.json` 的 `checks[].path` 去重得到。对每个路径分别运行 `git --git-dir=<裸库> rev-parse <完整提交>:<路径>`，比较候选与两个世界的 blob。最后核对批准 SHA 等于候选、`refs/heads/accepted` 等于接受记录的 `resultingHeadCommit`，以及候选和晋升提交的 tree 是否相同。短 SHA 仅用于界面显示。

## 六、落地与可证伪的验收

现有 MultiGraph 已消费带类型和依据的投影，节点按当前数组序号排四列。插入一个节点就可能改变后面多项的位置。第一步在 DSH 会话的只读适配器上按稳定引用保存位置与选择，对接 Work、Organization、Runtime、Reasoning、Boundary 等既有所有者。在前端将单个显示父节点用于排版包含，将多重成员资格放进独立的集合索引。React Flow 的 `parentId` 可表达单一几何容器。UI 自己的坐标和轮廓都不能回写成组织、世界或成员事实。[既有图组件](../../../web/src/MultiGraphView.tsx) · [React Flow 的子图](https://reactflow.dev/examples/grouping/sub-flows) · [DSH 会话槽位](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.5/packages/client/ui-conversation/src/client/contract/slots.ts)

| 验证的问题 | 对照及成功条件 |
| --- | --- |
| 布局是否忠实、可重复 | 同一依据重放两次，核对节点、动作边与集合成员。单次增量和切换轮廓应保持固定点及无关节点的相对位置。完整授权范围内，图的成员标记与集合名单逐项相等。隐藏来源、跨域无绑定、晚到事件及组织合并要各有反例。 |
| 合成样例能否拆开三种变化 | 顺序查看加入复核、生成注记、退出复核、组织换版。读者应指出哪次改变集合、哪次产生新工件、哪次才改变组织，查到退出者先前留下的成果。样例的角色、版本与动作均为合成记录。[可操作样例](prototype/structure.html) |
| 人是否更容易判断 | 同一 DSH 位置、同样的数据与文字，交叉安排「树＋列表」「自由节点图」「本提案」三个条件。让读者找双重成员、追一项交付、辨别退出与历史贡献、比较两个世界。分别记录误归属、把共享误读为通信、找回焦点的时间，以及打开原件的操作数。另用同坐标小图对照动画。 |
| 规模变化是否仍可读 | 从单人单事、两组并行、一个人多角色切到 50 条工作支线与 1,000 个事件的合成输入。测更新耗时、布局位移、遮挡、点选错误和过滤后的交集。检查键盘、灰阶、减少动效、窄屏和历史冻结。性能和读者效果须在原生挂载后另测。 |

首版研究核对了组织定义、组织演化、组织与联盟重叠、联邦边界成员四组既有回归，47/47 通过。首版样例在 Chromium 断网、启用减少动效、360、390、768、1440 像素宽度下逐步核对。每种宽度均检查五个时点、四位参与者和两组轮廓的 40 个成员判定，同时核对每个节点的中心、四角和名单。另查了工件出现与保留、组织目录的双重入口、键盘定位、沿比对表追到下一位参与者，以及视图切换后的选择。浏览器未发出外部请求。这些检查覆盖样例的已知数据；会话原生挂载、晚到或部分可见的数据、一般布局求解以及真实读者的表现仍待验证。

交接回放在 320、360、390、620、768、1024、1440 像素宽度下完成五步检查。每种宽度逐人核对两个集合，共 280 个判定，另核对工件出生、世界边界和动作的双方。连续播放能暂停在同一画面，恢复后依序到第五步停止；读者可固定一份工件，在当前时点重看它先前的签注或引用。刷新会恢复时点与固定对象，减少动效时可以读到同一条记录。验证只访问本机样例。
