# R4 签发与旧回执适用性

两组使用同一 R4 基线、原业务提示、原模型路由和独立会话。先 P 后 F，每会话最多 64 笔、30 分钟、单请求 240 秒。维护者计入同一窗口。金额和总 tokens 按量。新增 UNKNOWN 关闭后续准入。

候选按完整 HEAD 和冻结晚班上限逐格验请求功率，限幅前的任何超额触发拒签。原表回执可支持修订班表，须引用归档原表完整 SHA，核验实测班表 blob、四格半小时、车辆窗口和预约平移。冻结的工况材料受文件义务保护。模型须自行按适用记录重算电量与逐车余量。引用修订班表的路径继续按相同班表 blob 核验，真实维护者回传另从 trajectory 与台账核对。

两种入口的 Mock 均须在真实工具结果看到超限时段和幅度，然后提交合法修订，沿用原表回执取得签发，独立 10/10，自然退出，维护者请求为零。实跑只给业务目标。比较 R4 与已封存的 R7，逐项区分本席试排、维护者实测、缓存回读、签发和事后评分。核对变更前后 Git 工件，分别记录回执采纳和随后的决定，按角色拆出用量。旧 R4 的 2/10 与未知请求保留原判。
