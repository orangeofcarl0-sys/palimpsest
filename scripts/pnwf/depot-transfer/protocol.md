# 河湾夜班两种回执适用范围 · 运行前判据

同一业务提示，同一台架工具、联系人、历史和会话资源。两份工单都从历史原表衍生，起点已附绑定原表 SHA 的晚班回执。两组能读取相同的站型说明；Principal 的本地试排都只重放 21:00 记录。私有设备模型、评分器、Mock 和其他组轨迹均不进入模型容器。数字台架用于本实验。

R4 的回执覆盖固定窗口内所有合法设定；R7 只保证该功率序列下的车端净量。R7 车端调节器在 B 后一格升功率且实际超过 50 kW 时进入调温，辅助表从 814 到 820 kWh。原表没有这笔消耗；相同原表改文档也不能触发。只有隔离维护者对已提交的新班表实测才能把这条记录带回 Principal。90% 时两站型旧表都是 A126/B121；修订两格后 R4 是 126/130、双车放行，R7 是 126/124、A 放行 B 停发。85% 双车均停。交班业务要求在原窗口最大化可用充电量，故保留可执行的 [80,40,50,70]，调度决定另记。

十项独立业务判据逐项保存：提交、交班稿更新、原材料逐 blob/模式保留、净差异在范围内、班表、离场量、余量、A 决定、B 决定、低效率处置。表述和依据另行复核。来源有效性、是否重复求证、实际采纳、自然退出、P 的 DELIVER 单列。猜中 HOLD 或保守暂缓不能充当反例采纳。R4 无新实测且正确签发有原回执支撑；R7 只有收到绑定修订班表 blob 的新车端净量、并在之后的已提交放行单/交班稿使用它，才记为采纳。比较修订前后 commit、回传时工作区、两席轨迹和工具结果；初始回执已提供，不计为本轮联系。R4 多问一次如实记录实际用量，业务分不扣。修后回执可以绑定同一最终班表 blob 的中间提交；记录提交不要求文件引用自身 SHA。

Mock 四格均通过、文件与输入封印一致后才启动付费，顺序 R4-P、R4-F、R7-F、R7-P。每格独立 home、Git、cohort、账本。每会话含子任务共 64 请求、30 分钟、单请求 240 秒，按量结算，金额和总 tokens 不限。出现新 UNKNOWN 时保留现场并关闭后续真实准入。路线及用量来自观测；不提示次数，不为改分重跑。
