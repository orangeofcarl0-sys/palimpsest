# R4 证据说明和签发提示的拆分对照

基线、业务提示、原始档案、原表回执、维护者的隔离测量、签发判定及独立评分沿用上轮。按说明 P、说明 F、提示 F、提示 P 顺序运行，每格使用独立 DSH home、Git 副本、cohort 与账本。先验证全部四格 Mock，再按此顺序启动真实矩阵。每格 64 笔、30 分钟、单请求 240 秒，维护者计入本格，金额与总 tokens 按量。出现新 UNKNOWN 后停止后续准入，保留已运行格。

说明组使用上轮工具说明及本席试排中的实测适用规则。两种签发入口均保留原始逐格请求、限值及超限诊断，隐藏缺额字段；若仅少排，拒签并提示复查工单。提示组使用原有通用工具说明和本席试排范围，在签发入口保留少排时段和幅度，隐藏新增的来源优先级说明。原始晚班回执本有的适用信息、数值和业务材料两组均可读。宿主存储同一严格判定及实际返回给 DSH 的视图，最终独立验收使用原判定。

以 Principal 的可见动作和按调用 ID 配对的结果定时。读取含 50 和 70 的档案记为获得条件；主动计算或明确说明 01:30 的 20 kW 差额记为显式识别；直接从 50 改为 70 而未写出差值记为行为识别。第一次向 Principal 返回含具体少排量的预检或 DELIVER 结果是提示分界。并行批次按实际事件顺序处理。若未收到点名，报告实际修订和此前是否求证，单列维护者所回传的新信息。按放行单初稿、提交、复核与终稿顺序判断是否改判。Mock 的脚本化纠错只用于资格。历史无新增说明和少排提示的一轮以及两项同时开启的一轮作为背景，四条新轨迹不构成重复抽样。
